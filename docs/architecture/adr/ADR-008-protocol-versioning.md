# ADR-008: 易变协议的版本化、fixture 与上游同步

Status: **Accepted（机制已随 issue #7 落地，待上游首次变更时复核）**
Date: 2026-11-10
Related: RFC-0001 §5.3 / §16.7 / §23（R6）、ADR-003、issue #7

## 背景

WBI 签名、playurl 的风控参数、必要请求头这类协议细节有三个共同点：

1. **上游会改，且不预告。** 参数增删、魔数变化、算法微调都发生过。
2. **错了不报错。** 签名错、少一个风控参数，服务端返回的是普通业务
   错误码或一份降级的清晰度列表，而不是「签名无效」。现象与原因之间
   没有可追的线索。
3. **迁移期有两份实现。** Dart 基线与 Rust 新实现并存（RFC §5.3 的
   Stage 1）。只同步其中一份，差异会以上述形式静默爆发。

因此需要一个机制，让「协议变了而我们没跟上」这件事**在 CI 里以测试
失败的形式出现**，而不是在用户的播放器里以清晰度降级的形式出现。

## 决策

### 1. 协议快照版本号

`bili-protocol` 导出 `PROTOCOL_VERSION: u32`。凡因上游协议变化而改动
协议实现（新增/删除参数、算法调整、常量更新）都 +1。

### 2. 每份 fixture 带 `protocol_version`，golden 测试断言其与常量相等

fixture 停在旧版本时，逐项对照**可能仍然通过**——改动的恰好是用例没
覆盖的那部分。这时测试的绿色是假的。版本号对不上即失败，强制重新生成。

涉及的 fixture 与测试：

| fixture | 生成器 | 测试 |
| --- | --- | --- |
| `bili-protocol/tests/fixtures/wbi.json` | `tool/fixture-gen/wbi_fixture.dart` | `wbi_golden.rs` |
| `bili-api/tests/fixtures/playurl.json` | `tool/fixture-gen/playurl_fixture.dart` | `playurl_golden.rs` |

### 3. 期望值由 Dart 基线产出，不由 Rust 自证

每个生成器**逐字复制**基线的对应实现（而非 import）：复制的那份反映
基线此刻的真实行为，上游一改，重新生成就会与旧 fixture 产生差异。
Rust 测试只负责复现，不负责定义正确。

### 4. 随机值锁形状，不锁值

`dm_img_str` / `dm_cover_img_str` 每次请求都不同，无法对照固定期望。
对它们断言的是**不变量**：字节长度区间、base64 字母表、不含 `%`
（基线特意把字节下界设在 `0x26` 以避开它）。fixture 里则固定成占位值，
以便其余参数与签名仍可逐项比对。

### 5. 请求构造必须是纯函数

时间（`wts`）与随机 token 由调用方注入。否则同一输入每次产出不同查询
串，fixture 无从对照，剩下的只有肉眼比对。

### 6. 与基线的有意偏差，写在偏差发生处

不是所有基线行为都该照搬（例如 `MixinKeyCache` 改用自纪元起的日序号，
修掉基线只比较「日期中的日」导致跨月不失效的问题）。每处偏差在代码注释
里说明**偏差方向为何是安全的**。判据：偏差只能让请求更频繁地刷新状态或
更早地失败，不能让一个错误的值被当成有效值用下去。

### 7. 上游同步流程

沿用 RFC §16.7：固定 `UPSTREAM_COMMIT`，按同步窗口审计上游的 API/签名
改动。顺序是**先改 Rust 协议层与 fixture，再回头验证 Dart 基线的差异**，
避免「只同步了 Dart 修复，Rust 还停在旧协议」。每次改动在
`docs/architecture/protocol-changelog.md` 记一行。

## 不做什么

- **不做运行期协议协商。** 服务端不提供版本标识，版本号是我们自己的
  快照编号，只服务于 fixture 与变更记录，不参与任何请求。
- **不把缓存策略放进协议层。** key 存到哪里（Hive / 文件 / 内存）是宿主
  的决定；协议层只回答「这份 key 今天还新鲜吗」。

## 验证要求

- 每个 golden 测试都必须验证其**鉴别力**：故意改坏一项（删一个参数、
  动一个常量），测试必须变红并指名用例。issue #7 对 `fourk` 做过这项
  检查（删掉后 `ugc_minimal` 立即失败）。
- CI 的 `cargo test` 覆盖全部 fixture 对照（RFC §19）。
