## 背景

#130 立单于 2026-11-13，前提是「Slint 没有背板能力，所以玻璃必须自建
wgpu 管线」。**那个前提在立单三天后就不成立了**：Slint 1.19.0（2026-11-16）
给 `Rectangle` 加了 `backdrop-blur`。三轮 spike 之后，可选项与代价都有了
实测，这份 ADR 把取舍定下来。

一句话现状：**原生 `backdrop-blur` 解决了「模糊」，但解决不了折射与高光；
要折射与高光就必须拿到本帧真实背板，而拿背板只有一条路跑通了。**

## 决策一：玻璃走 GL 覆盖（`AfterRendering` + `NativeOpenGL`），不自建 wgpu 管线

在 Slint 的 `AfterRendering` 回调里，用 `glCopyTexSubImage2D` 把本帧已画完、
尚未 present 的帧缓冲拷进自己的纹理，再用自己的 GLSL 在其上绘制玻璃。

**为什么不是 wgpu**：`GraphicsAPI::WGPU30` 只有 `{instance, device, queue}`，
没有本帧的渲染目标，发不出 render pass（运行时证据见 `src/wgpu_probe.rs`）。
GL 没有这个问题——它有隐式的当前帧缓冲。

**为什么不是「上一帧回灌」**：滚动必拖影。
**为什么不是 fork Slint 或自定义 platform**：前者成本不成比例，后者的
`femtovg_renderer` 标着 `non-Android only`，Android 直接出局。

**证据**：Windows/FemtoVG 与 Android/Skia 两个后端各跑通一次，
`draw_fbo=0 read_fbo=0`，拷贝与绘制全程 `glGetError=0`。上游在
`femtovg/opengl.rs:212` 的注释里明确预期 notifier 会重新绑定帧缓冲，
说明这是支持的用法而非钻空子。

**已知的边界（见决策六）**：Apple 平台上 Slint 1.19 的 Skia 走的是
Metal-via-wgpu，这条路**大概率不通**。

## 决策二：背板捕获范围 = 玻璃矩形外扩 max(3σ, 折射强度)，全程 GPU 内，不回读 CPU

拷贝区域按 `max(3 × blur_radius, refraction_strength) × scale` 外扩；
shader 侧用 `u_backdrop_origin` / `u_backdrop_size` 换算 uv。

`3σ` 那一半与 Slint 原生 `backdrop-blur`「最远采到该值三倍」同口径。
**折射那一半是 2026-11-26 补的**：折射把采样点沿法线推出矩形最多
`refraction_strength` 个逻辑像素，Phase 1 漏算了它，于是 σ=0 的档（baseline，
以及决策四那个组合）边距是 0、外缘那 7px 一直在采 clamp 值。症状只是「边上
一圈颜色发直」，三轮都没看出来。

每帧的复制**只有一次**（`glCopyTexSubImage2D`），没有任何 CPU 回读或
重新上传。显存实测与按尺寸算出来的一致（1.87 MB 实测 / 1.91 MB 理论），
可以反过来确认「只有这几张纹理」。这回答 #130 关口 4。

**随之成立的一条约束**：两块玻璃相距小于 3σ 时会互相采到对方。这不是
实现缺陷，是这条路径的物理性质。组件库（#224）排布玻璃时必须知道它，
#130 P1 的「靠近时的玻璃融合」正是它的正面用法。

## 决策三：材质参数表是单一来源，放在 Rust，宿主只负责接入

`GlassMaterial`（现在在 `spikes/slint-glass/src/material.rs`）是玻璃观感的
唯一定义处：模糊半径**与级数**、折射强度与带宽、高光强度与带宽**与集中度**、
**顶边高光**、**光源方向与角速度**、Fresnel 指数与强度、表面渐变三档 alpha、
描边 alpha 与宽度、不透明度、圆角、**厚度**、**融合半径**。shader 与宿主控件
都只是它的消费者，**不得各自硬编码**。

Phase 2 之后 #130 参数表里的每一项都有实现了；`thickness` 的语义由本 ADR
决策七给出。**动画状态也在 Rust**（光源方向按 `Instant` 推，不按帧计数——
帧率在 60 和 120 之间变时转速不该跟着变）。

这条直接来自 AGENTS.md §2：换掉宿主框架时这张表不该重写。它也堵掉
#130 评论 §4 记的那个分歧风险——参数同时存在于 `shaders/liquid_glass.frag`
和 Rust 两处必然漂移。

**三档必须同时保留**：

- `FLUTTER_BASELINE`：与 Flutter 的 shader 路径逐项同式，**`blur_radius`
  按 0 使用**（Flutter 那边 shader 与 blur 是二选一，10 是回退档的值）。
  它是「像不像」的唯一参照物。
- `P0_TARGET`：在其上补模糊与 Fresnel，即本单 P0 的目标形态。
- `PHASE2_TARGET`：再补多尺度模糊、动态高光与融合。

只留最新那档的话，画面上的差别里分不清哪些是新能力、哪些是移植没对上。
`material.rs` 里有测试钉住「baseline 档里 Flutter 没有的能力必须全是关的」
——这条一旦被破坏，前面几轮的对照记录全部作废，而**画面上看不出来**。

**搬家时机**：这张表随 #224 迁进 `rust/crates/` 下的正式 crate，届时
`material.rs` 顶部那条「例外要写下来」的注释一并删除。在此之前它待在
spike 里，是因为不该把未验证的架构决策先写进产品代码。

## 决策四：模糊归原生还是归自绘，按质量档分；归原生时**材质层必须一并归自绘**

实测代价（Adreno 740，120Hz，每帧预算 8.33 ms；相对「连原生模糊都关」那个
地板的增量，七档对照见第四轮记录 §5）：

| 构成 | 每帧 GPU |
|---|---:|
| 原生 `backdrop-blur` | **+0.59 ms** |
| 自绘层（折射 + Fresnel + 高光 + 材质层） | **+0.24 ms** |
| 自绘模糊，单级 | **+1.70 ms** |
| 自绘模糊，再加两级（多尺度） | **+0.19 ms** |

自绘模糊比原生贵 **2.9 倍**，贵在全分辨率拷一张带边距的背板再降采样，而原生
那条在渲染器内部做，省掉这一拷。所以「原生负责模糊、自绘负责折射与高光」
这个组合值得要：合计 **+0.83 ms**，而全自绘三级是 +2.88 ms。

**2026-11-26：这个组合验过了，可用——但只有一种摆法可用。**

原 ADR 没有说清「渐变与描边归谁画」，而这一项决定成败：

| 摆法 | 原生那层 | 自绘那层 | 结果 |
|---|---|---|---|
| 原生画全套 | 模糊 + 渐变 + 1px 白描边 | 折射 + Fresnel + 高光 | ❌ 描边被折射**拖出第二道** |
| 原生只画模糊 | 只有模糊（透明、无描边、无阴影） | 折射 + Fresnel + 高光 + 渐变 + 描边 | ✅ 干净 |

判据是过圆头的一行亮度剖面：前者出现两个亮峰，相距 7 物理像素，正好是
`refraction_strength` 乘上 `rim` 衰减的那一份；后者单峰、单调下降。
数据见第四轮记录 §1。

**于是定下来：模糊归原生时，原生那条只开 `backdrop-blur`，渐变、描边、阴影
整个归自绘。** 这条在 Rust 侧由 `GlassQuality::needs_native_blur()` 表达——
它是质量档的一部分，不是宿主的布局偏好（理由同决策三）。

**代价是拿不到多尺度模糊**：原生 `backdrop-blur` 只有一档 σ，从边到心是个
常数（实测残余对比度 18.0 / 18.6 / 18.6，而自绘三级是 15.1 / 9.1 / 4.9）。
「边缘清楚、体部糊」只能自己画模糊，见决策七。这不是缺陷，是这一档的定义，
它直接决定了决策五那张表怎么排。

## 决策五：质量分档按**整条表面**升降，不逐效果开关

| 档 | 构成 | 每帧 GPU（相对地板） | 多尺度 |
|---|---|---:|:---:|
| High | 自绘三级多尺度模糊 + 折射 + Fresnel + 动态高光 | **+2.88 ms** | ✅ |
| Balanced | 原生 `backdrop-blur` + 自绘折射 + Fresnel + 静态 glint | **+0.83 ms** | ❌ |
| Low | 只有原生 `backdrop-blur`，自绘层整个不画 | **+0.59 ms** | ❌ |

全部实测（Adreno 740 / 120Hz / 12s 窗口，七档对照见第四轮记录 §5）。

**Balanced 就是决策四那个组合。** 它原本定的是「自绘单级模糊 + 简化折射」，
2026-11-26 实测之后改掉了：自绘单级 +2.69 ms，而 High 才 +2.88 ms——中间档和
顶档一样贵，等于没有中间档。

**Balanced 的折射不减半。** #130 的质量表写的是「简化折射」，但折射正是自绘
这层唯一不可替代的东西（原生给不了），砍它等于砍掉这一档存在的理由；真正贵的
是模糊，而模糊已经交给原生了。减的是高光：退回与 Flutter 同式的静态 glint。

**Low 不是「参数全填 0」**，是整个不挂自绘层——参数填 0 的话 shader 照样跑满
一遍采样与混合，那 0.24 ms 省不掉。Rust 侧由 `GlassQuality::draws_overlay()`
给这个判据，而不是让宿主去猜。

能力判定在材质层**做一次**，整条表面一起降级。这条沿用 Flutter 侧的现成先例
（`ImageFilter.isShaderFilterSupported` 为假时整体退到 `ImageFilter.blur(10)`，
见 #122 的验收记录），好处是降级后的观感是设计过的一档，而不是若干开关的
任意组合。降档规则与低端机判定由 Rust 统一管理，宿主不参与。

**低端机那一档（静态/缓存模糊）仍未定**，要设备，转 #225。

## 决策六：本阶段按**三端**承诺，Apple 平台单独立项

Slint 1.19.1 的 Skia 渲染器**没有独立的 Metal surface**：
`lib.rs:248` 的 `metal_wgpu_surface_factory` 把 Metal 走成 wgpu，
而 wgpu 变体没有渲染目标（决策一）。

| 平台 | notifier 变体 | GL 覆盖 | 依据 |
|---|---|---|---|
| Windows | `NativeOpenGL` | ✅ | 实测 |
| Android | `NativeOpenGL` | ✅ | 实测 |
| Linux | `NativeOpenGL` | 大概率 | 同桌面路径，**未验** |
| macOS | `WGPU30` | ❌ 推断不通 | 源码，**未验** |
| iOS | `WGPU30` | ❌ 推断不通 | 源码，**未验** |

**不承诺五端一致**。Apple 两端要么改用 GL 后端（macOS 上 GL 已废弃但仍
可用；iOS 要看 GLES），要么只给原生 `backdrop-blur`（Balanced 档），
要么另想办法。这件事排在 #225 最前面，**它决定玻璃是一套还是两套**。

## 决策七：多尺度模糊是**能力**不是优化；`thickness` 就是它的过渡深度

金字塔：第 0 级降到 1/4 边长、σ 用 `σ/4`；之后每级边长再减半、σ 固定 2.0。
等效 σ 按方差相加，σ=10 时四级依次 **10 / 18.9 / 37.0 / 73.7** 逻辑像素。
shader 按深度在第 0 级与最后一级之间插值。

**它不是为了省钱。** 折射靠背板里的高频细节沿法线错位，粗级已经把那些细节
糊没了；边缘要留细节、体部要糊，这个组合**单级拿不到**——σ 大则边缘的折射
没了，σ 小则体部不糊。省钱是副产品（多两级只要 +0.19 ms，因为那 1.70 ms 的
大头是带边距的全分辨率拷贝，后面几级不再付）。

**`thickness` 的语义在本 ADR 定下**：#130 的参数表只给了名字。这里定义成
「从细级过渡到粗级的深度，逻辑像素；0 表示整面都用最粗那级」。选它是因为
厚度正好接上唯一一个需要按深度插值的效果，不必再立一个参数。

默认三级而不是顶满四级：80px 高的胶囊上第四级等效 σ 73.7 已经超过形状本身。

## 决策八：形状与融合都在 SDF 里，三种形状是同一个 SDF

圆角矩形 / 圆 / 胶囊**不是三段代码**：圆角取到半高就是胶囊，宽高相等且圆角
取到半边就是圆。法线取 SDF 的解析梯度（不用中心差分：解析式是闭式的，差分
要多四次距离计算，步长还得跟着 scale 调）。

代进 `r = h/2` 之后，这两个函数逐项退化成 Flutter `liquid_glass.frag` 的那两
行——**所以这次推广没有动 baseline 档的像素**。这一点是硬要求：baseline 是
「像不像 Flutter」唯一的参照物，它一动，前面几轮的对照全部作废。推导写在
`shaders/glass_sdf.glsl` 的函数注释里，`material.rs` 里另有三个测试钉住
「baseline 里 Flutter 没有的能力必须全关」。

融合用 smooth union，**法线按同一个权重混**——不混的话颈部的法线会在两个形状
之间跳变，折射方向跟着跳，画面上是一条闪烁的硬缝。覆盖矩形改成所有形状的
并集外接框。代价上**没有量到额外开销**（4.79 vs 单形状 4.88 ms），不过两档的
玻璃面积不严格相同（融合档的主胶囊缩窄约 3% 以给圆让位），所以这条只是
「没量到」，不是「严格为零」。

融合半径与决策二那条「相距小于 3σ 会互相采到背板」是同一件事的两面：那条是
副作用，这条是把它用成效果。

一条会影响组件库的实测结论：**方向性高光在圆角矩形与胶囊上会整条直边一起亮**，
只有圆角处才有「光斑」——直边上法线处处相同。想要点状高光，形状得有曲率，
或者改用别的高光模型。见第四轮记录 §4。

## 不做什么

- **不 fork Slint。** 三轮下来没有一处需要它。
- **不往 Slint 渲染器里注入 WGSL。** 做不到，已有运行时证据；玻璃只能是
  独立一层。
- **不在 CI 里验收玻璃。** 托管 runner 只有软件光栅器，那种帧时间与显存
  写进文档比没有更坏（见 `docs/m0/VALIDATION-CAPABILITY.md`）。本 ADR 的
  每个数字都来自真机。
- **不据此动 Android 最低版本。** spike 的 `min_sdk = 31` 是探针自己的
  取值（要 `ANativeWindow_setFrameRate`），不是对 app 的主张。

## 未决与风险

1. **Apple 两端未验**，见决策六。挡着五端一致性，转 #225。
2. **低端机未验。** 现有数字出自 2023 年旗舰，#130 的风险恰恰在低端机。
   缺设备，转 #225。Balanced 档（+0.83 ms）大概率是低端机上唯一跑得动的
   自绘形态，但这是推测。
3. **Low 档的具体形态未定**（静态预模糊还是缓存、失效规则是什么）。
   要设备才谈得上，转 #225。
4. **功耗与温度未测**，采样窗口太短（每档 12 秒），热降频来不及发生。转 #226。
5. **桌面侧没有帧时间**：帧率被 vsync 钉死，Windows 上又没有 Adreno
   `gpubusy` 那种免 root 的占用计数。转 #226。
6. **滚动残影未看**：现有背景是匀速横移的彩带，不是真实列表滚动。
7. **`gpuclk` 读不到**（permission denied），DVFS 对占用率的影响无法彻底
   排除。120Hz 满负载下残留较小，但这条不确定性至今没关掉——
   复用这套测法之前先读第二轮记录 §3.4。
8. **`GlassPreset` 那五个预设仍然没有任何观感背书。** #130 只给了名字没给
   参数，Phase 2 只是把新字段按同一思路填了进去。排 #224。
9. **显存那一行的分辨率不够。** 多尺度两级理论上只多 65 KB，`dumpsys meminfo`
   的 Graphics 行却报 +0.48 MB。这一行包含 surface 与驱动自己的分配，
   0.5 MB 这个量级不能当证据用。
10. **按压/拖动形变（P1）没做**，它要手势，而实验台连输入都没接。排 #224。
