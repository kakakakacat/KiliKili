# QA-001：端到端功能矩阵与发布前清单

状态：**测试方案，待按候选版本执行**
关联：[RFC-0001 §8–9](../architecture/RFC-0001-rust-slint-migration.md)、[验证能力矩阵](../m0/VALIDATION-CAPABILITY.md)、[M0 基线](../m0/BASELINE.md)、[Issue #13](https://github.com/kakakakacat/KiliKili/issues/13)

本文规定如何验收一个发布候选版本，不代表这些场景已经通过。每次发布复制文末记录模板，填写版本、设备、结果和证据链接。`PASS` 必须有实际操作结果；无法执行时记 `BLOCKED` 或 `NOT TESTED`，不可用构建成功代替运行时通过。

## 1. 执行约定

- 使用同一候选 commit 构建的 **Release 产物**。记录 commit、版本号、产物哈希、平台、系统版本、设备型号、安装方式、测试账号类型和执行时间。日志与截图须删除 Cookie、token、手机号、设备标识、视频和用户的私人信息。
- 准备匿名态、普通登录态各一套；涉及账号的场景只用可控制的测试账号和内容。准备一条可公开播放、含弹幕和评论的固定 UGC 视频，并记录其清晰度、时长及是否 DASH 分轨。样本失效时记录替代样本及原因。
- 功能用真实设备执行。Android、iOS、macOS、Windows 的可用性及 iOS 签名前置条件见[验证能力矩阵](../m0/VALIDATION-CAPABILITY.md)。Linux 当前只有构建与静态产物检查，GUI 验收记 `NOT TESTED`，不能写作通过。
- 对每条用例记录 `PASS / FAIL / BLOCKED / NOT TESTED`、执行人、设备、步骤中的实际结果、截图或脱敏日志、缺陷链接。`BLOCKED` 用于环境或外部服务阻断；`FAIL` 用于已观察到产品行为不符。修复后重测原场景及关联场景。
- **P0** 是发布硬门槛：任一目标平台的 P0 `FAIL` 或 `NOT TESTED`，不得宣称该平台验收通过。`BLOCKED` 需写明原因、替代证据和发布决策人；不能自动视为通过。P1 缺陷需要明确处置结论。平台未计划发布时标注 `N/A` 和理由。

## 2. 功能矩阵

所有目标平台至少跑匿名主链路。登录、后台、触摸与桌面交互按平台能力执行；同一用例在不同平台要分别记录结果。步骤以当前 Flutter 客户端为准，Phase 2 更换 UI 后沿用行为目标并更新入口名称。

| ID | 优先级 | 场景与操作 | 通过标准 |
|---|---|---|---|
| F01 | P0 | 全新安装后启动；不登录进入首页，切换推荐/热门并下拉刷新 | 启动可交互；列表有内容或明确空态/错误态；刷新可结束，不无限转圈或崩溃 |
| F02 | P0 | 从首页进入固定 UGC 视频详情，返回首页，再次进入 | 标题、作者、封面、分 P/剧集入口与服务端一致；来回导航无旧数据串页或崩溃 |
| F03 | P0 | 搜索固定关键词，切换综合/视频分类，翻页，进入结果 | 关键词与分页结果对应；无重复页、错位或旧查询覆盖新查询；结果可进入详情 |
| F04 | P0 | 匿名播放固定视频，等待首帧和音频，暂停/继续，切换清晰度或分 P | 画面与声音正常；控制状态和实际播放一致；切换后继续播放，无长时间黑屏或资源错误 |
| F05 | P0 | 播放中向前、向后 Seek，连续快速 Seek，再暂停和恢复 | 最终画面/进度落在最后一次目标附近；不会跳回旧位置，音画保持同步；旧会话事件不覆盖新会话 |
| F06 | P0 | 进入和退出全屏，旋转设备或调整桌面窗口，再返回页面 | 画面比例、控制层和触摸/鼠标区域正确；退出后播放器仍可控制，无黑屏、崩溃或悬挂声音 |
| F07 | P0 | 打开弹幕，观察与画面同步；Seek（前跳/后跳）、暂停、倍速、**退到后台再回前台**、切换视频后再观察 | 弹幕可见且时间匹配；暂停时停住，Seek 后没有旧弹幕残留且立刻接上新位置；**回前台后继续飘当前位置的弹幕，不得先飘出视频开头的那一批**（issue #89）；切换视频后不混入上一条弹幕 |
| F08 | P0 | 进入评论区，滚动加载并打开楼中楼回复；返回详情 | 评论与当前视频对应，分页无明显重复/丢页；正文、表情及回复能显示；返回后页面可继续操作 |
| F09 | P0 | 用测试账号登录，重启应用，访问首页、详情和评论；再退出登录 | 登录态保持且个人信息正确；退出后恢复匿名状态，不残留前一账号内容；账号操作不泄露到日志 |
| F10 | P0 | 播放中断网，等待错误提示，再恢复网络并重试；首页/搜索各重复一次 | 请求有终止或明确重试入口；恢复后可继续使用，无无限请求、重复提交或持续空白页 |
| F11 | P0 | 用旧版安装包创建设置、观看进度、搜索历史和测试账号状态；**原地升级**候选版并逐项核对 | 已有数据可读且不损坏；无法迁移的字段有已批准的迁移/回退方案；升级失败不得清空旧数据 |
| F12 | P1 | 移动端播放时切后台、锁屏、回前台；桌面端最小化/恢复窗口 | 行为符合当前设置；恢复后画面、声音、进度和控制状态一致，没有重复播放器或旧事件；弹幕按 F07 的标准一并核对 |
| F13 | P1 | 评论/搜索/详情在弱网、空结果和服务端错误下操作 | 显示可理解的状态与重试入口；返回导航仍可用；错误不被误报为成功 |

**F07 与 F12 为什么必须真机**：进度游标的判据（`bili_danmaku::cursor`）由 Rust
单测与 `test/bridge/danmaku_bridge_test.dart` 钉住，但它的**输入**——播放器在
回前台时吐出的那串 position——只有真实播放器才会产生。CI 全绿只说明「给定这串
进度，判得对」，不说明真机上那串进度长什么样。issue #89 就是这么漏过去的。

**F11 的数据边界**：当前 `GStorage.exportAllSettings()` 只包含 `setting` 与 `video` 两个 box，不能作为账号、`historyWord`、`watchProgress` 的完整备份。升级测试要使用可恢复的测试设备或独立副本，先留好旧版数据和回退包；不得在唯一的真实用户数据上试验。相关代码见 `lib/utils/storage.dart`。

### 2.1 typed 直连迁移的待确认项

ADR-011 决策五把对照机制定为「Rust 冻结快照 + Dart parity 测试」。两者**只能证明 Rust 与迁移前的 Dart 行为一致**，前提是 fixture 反映真实响应。部分接口匿名取不到（要登录态）或拿不到可用的入参，其 fixture 是**手工构造**的：它证明映射自洽，不证明我们对协议的理解正确。这些路径必须在发布前用真机各走一遍，CI 全绿不能替代。

| ID | 优先级 | 路径（切片） | 手工 fixture 的原因 | 操作与通过标准 |
|---|---|---|---|---|
| M01 | P0 | AI 总结、带字幕/看点的播放信息（S3 #53） | 要登录态，匿名是 `code -101` | 登录后在有 AI 总结的视频上打开总结面板、切字幕、看分段看点；内容与网页端一致，不是空白或错位 |
| M02 | P1 | 评论区开关状态、表情包面板（S1 #51） | 要登录态（匿名分别是 `code -101` 与 `packages: null`） | 用 UP 主账号打开自己稿件的「评论精选/关闭评论」菜单；在评论框打开表情面板，各组图标与文字表情都能插入 |
| M03 | P1 | 评论 shadow ban 自检（S1 #51） | fixture 真实，但**匿名视角**这一行为只能真机验 | 对自己发的一条正常评论执行自检，结果应为「评论正常」；对已知被限制的评论应给出 shadow ban 判定且不误报 |
| M04 | P1 | 音乐页详情与相关推荐（S15 #66） | 站内没有公开入口能枚举 `music_id`，fixture 手工构造 | 从带 BGM 的视频进入音乐页：标题/艺人/专辑/发行日期、热度曲线方向（左旧右新）、成就标签顺序、相关推荐列表与标签均正常 |
| M05 | P1 | 黑名单、云端弹幕屏蔽规则（S15 #66） | 账号自己的数据，匿名取不到 | 登录后打开黑名单列表（分页到底）、打开弹幕屏蔽规则三个 Tab；条数与网页端一致，新增/删除后列表同步 |
| M06 | P1 | 电竞赛事卡片与详情（S15 #66） | 详情 fixture 真实，但搜索卡片那条键名不同，只有真机能确认两条路径都对 | 搜索一个正在进行的赛事，综合页出现赛事卡片并能点进详情；比分、赛段、队伍与直播入口正确 |
| M07 | P0 | 直播取流与画质切换（S11a 第二批 / #61） | 七份 fixture 全部按基线 `fromJson` 手工构造；真实响应里 `stream → format → codec` 这棵树的形状随房间能力与请求的 `protocol`/`format`/`codec`/`ptype`/`dolby`/`panorama` 变化，高档位（4K、杜比）还要特定房间才出现，匿名枚举不到 | 打开一个直播中的房间能起播；画质菜单列出的档位与网页端一致；**切换画质后以服务端返回的那一档回填**——请求 4K 但房间只到原画时，选择器应显示原画而不是停在 4K；开「仅音频」能继续播；未开播的房间给出「当前直播间未开播」而不是空白或崩溃 |

| M10 | P0 | **视频取流与起播**（#79） | 三份 fixture 覆盖 UGC DASH / OGV 带进度与多语言 / PUGV 降级整段流，但取流是**唯一一条「错了就黑屏」的链路**，且四条接口路径（UGC / OGV playview / PGC 降级 / PUGV 降级）与三条重试分支（DRM 降级、UGC→PGC、两者不叠加）只有真实响应才走得全 | 逐项起播：UGC、番剧、课堂（PUGV）、互动视频、已下载的离线条目。另外要确认：**切换清晰度**后仍能播且菜单停在选中档；**清晰度菜单档位补齐**（起播后再取一次的那批低档位要出现在菜单里）；**多语言音轨**菜单顺序为中文在前、AI 配音在后且标题带「（AI）」；番剧**片头片尾跳过**按钮出现在正确位置；**音量均衡**开启后音量平稳（loudnorm 参数已下沉 Rust）；**投屏**仍能拉起 DLNA 页 |
| M11 | P1 | **CDN 选路**（#79） | 选路规则（镜像站改 host、`os=mcdn` 走 tf 代理、`szbdyd.com` 换回源站、Akamai 保留自带签名）下沉 Rust，单元测试用的是构造地址，真实签名地址只能真机验 | 在设置里逐个切换 CDN（至少覆盖 ali / backupUrl / baseUrl / akamai），每次切换后起播同一个视频：都能播且不出现 403；打开「音频不走 CDN」后音频地址保持接口原样仍能播 |

| M12 | P1 | **云端弹幕屏蔽规则的新增与删除**（#66 / ADR-013） | 仓库头两条走 Rust 的**写操作**。请求面由单测与桥接测试两头钉住，但钉的是「我们构造的表单长什么样」；**服务端认不认**这套 content-type 与字段名，只有真机能答。另外 `csrf` 的注入点从 126 处散写改成了一处，错了全线写操作一起错 | 登录后打开弹幕屏蔽页：新增一条关键词、一条正则、一条用户屏蔽，三条都应出现在对应 Tab 且**刷新后仍在**（说明服务端真收下了，不是只改了本地列表）；逐条删除，删完刷新应确实消失；在弹幕举报里勾「同时拉黑」，该用户应出现在「用户」Tab。**未登录时**新增应给出「账号未登录」而不是「校验失败」——后者说明 csrf 被伪造成了空串 |

执行记录按 §6 的模板填写；`FAIL` 时同时修正对应 fixture 并重新生成冻结快照，不要只改代码。

### 2.2 竖版封面大卡片的人工验证（issue #108）

竖版卡片改成「整张封面 + 底部叠加文案」，遮罩配色由 `bili_core::cover_scrim`
按封面取色算出。Rust 单测钉住的是「给定一张缩略图，算出的对比度达标」；
**它不保证屏幕上好看、也不保证取到的是那张封面**——缩略图由宿主解码，
解码失败、封面换了、滚动复用卡片都只有真机能验。

| ID | 优先级 | 路径 | 操作与通过标准 |
|---|---|---|---|
| U01 | P1 | 首页推荐、直播（首页/关注/分区/搜索）、番剧（时间表/索引/追番）、UP 主主页与投币/点赞列表 | 这些页面的卡片都是大封面 + 底部叠加文案，没有漏网的旧样式；标题、播放/弹幕、分区、围观数都在底部遮罩上，**UP 名/主播名在封面左上角、时长等角标在右上角**，两处都自带深色底不随封面变色；卡片有可见的投影 |
| U02 | P1 | 浅色封面、深色封面、高对比杂色封面各找一张 | 遮罩随封面变色且明暗跟着翻（浅封面应给浅遮罩 + 深文字）；三种封面上标题与辅助文字都清楚可读，没有「白字压白底」 |
| U03 | P1 | 弱网下进推荐页并盯住卡片陆续出图的那几秒；找一条封面 404 的稿件；下拉刷新时观察骨架 | **骨架和还没出图的卡片都不画遮罩**，遮罩跟着封面一起淡入，不该先出现一条深色带再变色；封面 404 或压根没有封面时落到固定的深遮罩 + 白字，文字仍可读；骨架与加载完的卡片高度一致，不发生重排 |
| U04 | P1 | 推荐流快速滚动 1 分钟后回滚 | 回滚到的卡片颜色与下滑时一致，不串色（列表项复用）；取色不造成可感的卡顿——量化走 P04 |
| U05 | P1 | 手机与平板、浅色与深色主题各走一遍；把系统字号调到最大 | 布局不破；长标题按行数截断而不是溢出；**超长 UP 名在左上角截断而不是顶到时长角标上**；大字号下文案仍不盖住大半张封面 |
| U06 | P1 | 在设置里把「主页卡片宽度」调到最小和最大各看一次 | 列数变化时卡片仍是 4:3，封面不被压扁；最窄那一档下标题仍有两行、UP 名与时长不重叠 |

**为什么 U02 不能靠单测**：Rust 的用例用的是纯色与棋盘图，真实封面是渐变 +
主体 + 水印。单测能证明算法在它见过的分布上达标，证明不了真实封面的分布。

## 3. 平台与证据覆盖

| 平台 | 发布候选需执行 | 当前能力边界 |
|---|---|---|
| Android | F01–F13；重点记录旋转、硬解、后台和断网 | 有 Android 实机；产物构建需手动触发 |
| iOS | F01–F13；重点记录全屏、后台、PiP（若本版本承诺） | 有 iOS 实机，但当前签名配置仍阻碍真机安装；未解除前记 `BLOCKED` |
| macOS | F01–F13 中适用项；重点记录窗口生命周期与全屏 | 有本机 GUI 与硬解验证环境 |
| Windows | F01–F13 中适用项；重点记录安装、窗口与硬解 | 有独立设备；不能以 Actions 构建替代 GUI 操作 |
| Linux | 构建、解包、原生库与依赖检查；功能项记 `NOT TESTED` | 目前无可用 Linux GUI/硬解验收环境，按 best-effort 发布范围单独披露 |

自动检查由 `ci.yml` 统一触发：每个 PR 和 main 提交都会跑 `rust.yml`（Rust 检查与冻结快照）、`flutter-test.yml`（Dart 基线对照与真实 FFI）、Android Release 开发包构建及 `libbridge_flutter.so` 产物检查；`regression gate` 要求这些 job 全部成功。每日定时运行还会调用 iOS、macOS、Windows、Linux 的既有打包 workflow；手动运行 CI 时可用 `full_platforms` 请求相同的全平台构建。若启用分支保护，应把 `regression gate` 设为必过检查。CI 的固定 fixture 对照不访问上游实时接口，基线版本见 [M0 基线](../m0/BASELINE.md)；更新快照须在 PR 中审查差异并重跑 Dart parity，不得在 CI 中设置 `UPDATE_GOLDEN`。

自动构建仍只证明产物可打包；它不能验收视频首帧、硬解、PiP、后台音频或升级后的真实用户数据。每个发布候选仍须填入 workflow run 链接、真机执行记录，并对目标平台的最终产物运行 `python3 tool/inspect-artifact.py <artifact> --require <原生库文件名>`。实际库名按平台产物确定，不能只看构建日志或包体积。产物检查方法见[发布产物复盘](../m0/2026-11-10-RELEASE-REVIEW.md)。

## 4. 性能采样场景

本节定义采样方法，**不预填基线数值**。同一平台只比较同一台设备上的旧版基线和候选版：固定系统版本、刷新率、电源/充电状态、亮度、音量、网络、视频样本、清晰度、弹幕设置与账号状态；记录工具版本和环境温度。先预热一次，再交替采样旧版与候选版各至少 5 次，保存每次原始值及 p50/p95；样本不足以稳定估计 p95 时同时列出最大值，不把单次波动当作结论。测试中改变条件必须重采双方。

| ID | 指标 | 固定操作及记录值 | 判定方式 |
|---|---|---|---|
| P01 | 冷启动 | 杀进程后点击图标至首页可交互；记录每次毫秒数、p50/p95 | 与同设备旧版相比；退化需定位原因，不用 CI runner 数据 |
| P02 | 内存 | 空闲首页、长列表滚动 5 分钟、1080p 播放 10 分钟；记录 RSS/PSS、GPU 内存、峰值及结束值 | 不持续增长；峰值差异有解释 |
| P03 | CPU | 固定 1080p 视频与弹幕密度，稳态播放 10 分钟；记录平均/峰值和硬解状态 | 与同设备基线比较，记录软/硬解变化 |
| P04 | 帧耗时 | 首页快速滚动及视频弹幕各 2 分钟；记录 p95/p99、丢帧数、设备刷新率 | 依据实际刷新率解释预算与退化，不混合不同刷新率设备 |
| P05 | Seek 延迟 | 同一视频固定目标位置，前跳/后跳各 5 次；从操作到有效新画面计时 | 记录每次值与失败次数；与基线比较 |
| P06 | 网络恢复 | 固定弱网、断线 30 秒、恢复；记录超时、重试次数、首帧恢复时间和请求数 | 无无限重试或请求风暴；功能行为同时满足 F10 |
| P07 | 电量/能耗 | 同亮度音量和网络播放同一 1080p 视频 30 分钟；记录电量变化及系统能耗工具数据 | 同设备 A/B 比较；温度或后台负载异常时重测 |
| P08 | 安装体积 | 对同架构 Release 产物记录字节数、内含原生库及相对上版增量 | 每次增量有原因；构建/产物检查通过 |

性能门槛采用 [RFC-0001 §8.1](../architecture/RFC-0001-rust-slint-migration.md) 的原则：冷启动、CPU、Seek 不劣于同设备基线；内存无持续增长；包体增量可解释。尚无数值基线时先记录 `NO BASELINE`，不得填写 `PASS` 或声称性能改善。硬解、PiP、后台行为与渲染性能不能由虚拟化 CI runner 验收。

## 5. 发布前决策清单

逐项勾选并附证据；未满足项写缺陷、影响平台和处置决定。清单是发布门槛的记录，不表示当前版本已具备发布条件。

- [ ] 候选 commit、版本号、Release 产物哈希固定；后续任何代码或打包改动重新生成候选记录。
- [ ] `regression gate` 通过；记录本次 CI 的 run 链接。若候选 commit 未经历全平台定时构建，手动以 `full_platforms` 运行 CI；记录构建结果、安装包签名/版本信息，并用 `inspect-artifact.py` 核对最终产物的原生库与依赖。
- [ ] `flutter-test.yml`、`rust.yml` 的全部检查通过；确认 bridge job 实际加载原生库，未将跳过的测试写作通过。
- [ ] 每个目标平台完成 F01–F11；适用的 F12–F13 已执行。登录态、断网恢复和旧版原地升级都有实际设备证据。
- [ ] Android、iOS、macOS、Windows 的播放、Seek、全屏、弹幕、前后台或窗口生命周期经过实际设备验收；iOS 真机签名问题已解决或该平台不纳入本次发布。
- [ ] P01–P08 已按固定设备协议采样；缺少基线、回归或未覆盖的平台在发布说明中明确记录，不把 CI 性能作为对照。
- [ ] 所有 P0 失败已修复并复测；P1 缺陷有负责人、影响与处置结论；`BLOCKED` / `NOT TESTED` 没有被填作 `PASS`。
- [ ] 安装、覆盖升级和必要时回退均可操作；用户设置、观看进度与账号数据未丢失；测试账号和脱敏材料已清理。
- [ ] 发布说明写明目标平台、已知限制、验证范围；许可证和资源来源检查完成（[RFC-0001 §9](../architecture/RFC-0001-rust-slint-migration.md)）。
- [ ] 发布负责人查看本次证据与未解决项，记录准予发布或延迟发布的决定。
