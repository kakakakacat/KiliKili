# #127：未登录首页导航加载采样

2026-11-26，产品源码 `fe32a637d`。这是候选版当前行为的测量，**没有旧版 A/B 数据，不作为性能改善结论**。登录态另测，不用匿名结果推断登录后的动态内容和个人数据加载。

## 环境与方法

- DN-ENG41，SM6225，Android 14，640×960，320dpi，60Hz。
- 真机 arm64 profile/AOT；Flutter 3.47.9；独立包名 `io.github.kakacat.kilikili.navprofile`，不覆盖原 dev 包。
- 充电、100% 电量；电池温度开始 29.8°C、结束 30.0°C。同一网络、默认页面数据，未冻结实时首页推荐响应。
- 默认浅色主题，悬浮玻璃底栏，64 逻辑像素；**关闭首页切换动画**，因此这里不包含原先强制 240ms 转场。
- 先预热；每个目标页启动 5 次新进程，每进程先展示首页 6 秒，再首次进入目标并回访两次。首次指进程内首次进入，未清除磁盘图片/着色器缓存；每页首次 n=5、回访 n=10。
- 自动调用真实 `MainController.setIndex`。起点为导航回调，不包含物理触摸到 Android/Flutter 分发的等待。
- 在目标页可见的合成帧后记录 frameNumber，再关联 `FrameTiming.rasterFinish`。它表示**光栅完成**，不等于面板实际显示；包含到下一次刷新可能还有等待。复用页面层的回访也检查可见区域，不依赖子树重新 paint。
- `data_terminal` 是 10ms 轮询观察到页面列表终态的时间，且先等目标帧到位；不应把它当成精确 HTTP 完成时间。`request_result` 直接记录 await 返回点，只有控制器类型和结果类型，不记录账号、正文或 URL。匿名“我的”不请求页面数据，数据终态列不适用。

## 结果

单位 ms；中位数（最小–最大）。样本较少，同时保留全部原始值，不报告不稳定的 p95。

| 页面 | 进入 | 导航回调到首帧光栅完成 | 该帧 UI 阶段 | 该帧 Raster 阶段 | 数据终态观察时间 |
|---|---|---:|---:|---:|---:|
| 动态 | 首次 | 92.83（79.26–94.81） | 53.72（47.08–62.22） | 20.48（18.75–28.40） | 196.62（182.65–225.68） |
| 动态 | 回访 | 51.07（23.13–63.59） | 26.70（10.71–35.19） | 7.83（6.11–8.64） | 44.84（16.06–57.71） |
| 我的 | 首次 | 64.18（45.00–81.14） | 39.42（29.37–53.96） | 11.75（10.26–16.24） | 不适用：未登录不请求 |
| 我的 | 回访 | 51.06（39.12–59.84） | 29.61（22.10–37.97） | 6.75（5.77–11.11） | 不适用：未登录不请求 |

记录器和日志本身有少量开销，未从数值中扣除。

选中态更新中位数：动态首次 0.64ms、回访 0.66ms；我的首次 0.37ms、回访 0.67ms。

动态首次请求均返回未登录错误：UP 列表控制器的 await 返回中位数 155.65ms，动态列表 196.28ms。首帧光栅处理在这些请求完成前已完成；请求终态仍会影响登录提示内容何时出现。

这些数据支持“动态首次进入比回访有额外开销”，但一帧的 UI/Raster 时间包含整帧工作，**不能把全部时间直接归因于目标页初始化或玻璃背景**。尚未采集 Dart CPU 调用栈，也未测登录后内容、其他底栏样式和旧版对照；不据此宣布 #127 已解决。
