# 短信登录交互调整（#140）

用户已确认现有 Android 修复版可以登录；追加要求是验证码弹窗自适应屏幕、获取验证码后聚焦输入框、六位验证码自动登录。

验证码 WebView 使用居中 Dialog，按可用区域保留边距并限制最大尺寸；手机、平板、横屏和键盘出现时均不能溢出。保留加载、错误、超时和关闭入口，不修改验证码请求或签名。iOS 原生 SDK 分支仍沿用原生 UI。

验证码输入使用六位数字限制及系统一次性验证码 autofill 提示。点击获取验证码立即聚焦，短信发送成功后再次聚焦，以覆盖图形验证关闭的情况。六位数字输入或粘贴时自动提交；自动和手动提交共用控制器并发保护，异常后解除保护、允许编辑重试。登录请求使用开始提交时的输入快照，避免异步取公钥期间输入变化导致串用。

输入事件和自动提交暂留 Flutter，以复用尚未迁移的登录控制器，随 #65 登录迁移一起处理；在代码及 issue 留下例外。布局、焦点和系统输入法仍属于宿主 UI。

验证：Widget 测试覆盖输入长度、数字过滤、粘贴、焦点、并发与失败重试；弹窗外壳测试覆盖手机、平板、窄屏、横屏和键盘边距；已有验证码脚本测试继续通过。运行 Dart 分析及 Android 构建，覆盖安装到已连接设备，实际短信收发由用户完成。
